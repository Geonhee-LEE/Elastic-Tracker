01MINCO란 무엇인가

이 계열 전체의 배경 — Wang et al., IEEE T-RO 2022 (arXiv:2103.00190)

MINCO는 궤적 최적화 알고리즘이 아니라 궤적을 표현하는 방식입니다. "최소 제어 노력(minimum control effort) 궤적은 웨이포인트와 시간 배분만으로 이미 결정되어 있다"는 정리 하나에서 출발해, 나머지 자유도를 전부 소거해 버립니다. 이름 그대로 MINimum COntrol의 약자입니다.

출발점 — 무엇이 이미 정해져 있는가

s중 적분기(integrator chain)에 대한 무제약 다단계 제어 노력 최소화 문제를 생각합니다. 즉 시작·끝 상태가 고정되고 중간에 M−1개의 웨이포인트를 지나야 할 때 ∫‖p(s)‖2 를 최소화하는 궤적을 찾는 문제입니다.

논문의 Theorem 2가 그 해의 필요충분조건을 줍니다. 최적 궤적은

  • 각 조각이 차수 2s − 1의 다항식이고,
  • 중간 시각 ti에서 2s − di − 1번 연속 미분 가능하며,
  • 경계 조건을 만족합니다.

결정적인 대목은 이것입니다 — 비용 함수를 한 번도 평가하지 않고 이 조건만으로 최적해를 직접 구성할 수 있고, 그 해가 유일합니다. 그래서 다항식 계수 c는 더 이상 자유 변수가 아니라 (q, T)의 함수가 됩니다.

TMINCO = { p(t) : [0,T] ↦ Rm | c= M (q,T) , T≻0 }

q = (q₁ … qM−1), 중간 웨이포인트 · T = (T₁ … TM)⊤, 각 조각의 소요 시간 · c ∈ ℝ2Ms×m, 다항식 계수 — q와 T로부터 유일하게 결정됩니다
표기 주의 — 논문은 조각 수를 M으로, Elastic-Tracker 코드는 N_으로 씁니다. 이 문서에서는 논문을 인용할 때 M, 코드를 인용할 때 N을 그대로 두었습니다. 같은 것입니다.

계수는 O(M)에 나온다

연속성 조건과 경계 조건을 전부 쌓으면 계수에 대한 선형 시스템이 됩니다. 그리고 조각 i의 조건은 이웃 조각하고만 엮이므로, 그 행렬은 대역폭 O(s)의 밴디드 행렬입니다.

M(T) c = b(q) , M∈ R2Ms×2Ms

밴디드 PLU 분해로 O(M) — 조각 수에 선형입니다. 조밀 행렬로 풀면 O(M³)일 문제입니다.

그래디언트도 O(M)에 돌아온다

이게 없으면 표현만 예쁘고 쓸모가 없습니다. 비용 F(c, T)의 그래디언트 ∂F/∂c, ∂F/∂T를 결정변수 쪽 ∂H/∂q, ∂H/∂T로 되돌려야 하는데, 같은 밴디드 구조를 전치해서 한 번 더 풀면 끝납니다.

M⊤ G = ∂F∂c ∂H∂Ti = ∂F∂Ti − Tr { Gi⊤ ∂Ei∂Ti ci }

전방 평가도 O(M), 역전파도 O(M). 이 대칭성이 MINCO의 실질적 가치입니다 — L-BFGS가 요구하는 값 하나 + 그래디언트 하나를 둘 다 선형 시간에 줍니다.

차수 s가 정하는 것

s최소화 대상다항식 차수 2s−1이 계열에서
2가속도 (min acceleration)3 — 3차GCOPTER가 지원
3저크 (min jerk)5 — 5차Elastic-Tracker · EGO-Planner-v2 — MinJerkOpt, PolyTraj.order = 5
4스냅 (min snap)7 — 7차GCOPTER가 지원

쿼드로터에서 저크·스냅이 특별한 이유는 미분평탄성(differential flatness) 때문입니다. 위치의 3계·4계 미분이 바디레이트·모터 입력과 직접 연결되므로, 그걸 최소화하면 액추에이터에 거는 요구가 작아집니다. 다섯 저장소 중 넷이 s = 3을 씁니다.

에너지 최소화가 아닙니다 흔한 오해라 짚어 둡니다. 최소화되는 것은 ∫‖p⁽ˢ⁾‖² dt이고, 이것은 제어 노력(control effort)입니다 — 이름 자체가 MINimum COntrol이지 minimum energy가 아닙니다.

쿼드로터 에너지의 대부분은 호버링 추력이 먹습니다. 가만히 떠 있어도 mg를 계속 내야 하니까요. 추력은 가속도(2계)에 대응하지 저크·스냅에 대응하지 않습니다. 최소 스냅 궤적은 에너지 최적이 전혀 아닙니다 — 실제로 에너지를 줄이려면 추력의 적분을 목적함수에 넣어야 하는데, 이 계열은 아무도 그렇게 하지 않습니다.

대신 얻는 것은 셋입니다.
① 액추에이터 여유 — 스냅 → 각가속도 → 토크이고, 쿼드로터의 롤·피치 토크는 마주 보는 로터 간 추력 차이로 만듭니다. 스냅이 크면 로터 RPM이 크게 벌어져 max_rpm 35000에 붙거나 min_rpm 1200 아래로 떨어집니다. 포화되는 순간 제어가 무너집니다.
② 물리적 재현 가능성 — 모터는 1차 지연입니다 (quadrotor_dynamics.hpp:134, τ = 0.03333 s → 차단 약 4.8 Hz). 그보다 빠른 스냅 성분은 명령해도 모터가 못 따라옵니다.
③ 수학적 편의 — 하필 L2 노름의 적분이라야 Theorem 2가 성립합니다. 다른 비용으로 바꾸면 MINCO 자체가 성립하지 않습니다.

Elastic-Tracker에는 하나 더 있습니다 — 바디레이트가 작으면 카메라가 덜 흔들립니다. 가시성이 목적인 저장소라 이건 부수 효과가 아니라 본론에 가깝습니다.

그래서 무엇이 달라지는가

이 문제를 정직하게 쓰면 이렇게 생겼습니다. 회랑 5개(N = 10) 기준입니다. 

min  J(c, T)                       c = 다항식 계수 6N×3 = 180개,  T = 구간 시간 10개

s.t. 조각 i 끝 = 조각 i+1 시작       등식 제약 135개 — 위치·속도·가속도·저크·스냅 × 9지점 × 3축
     p(0)=p₀, v(0)=v₀, a(0)=a₀ …    등식 제약 18개 — 경계 조건
     Tᵢ > 0,   ΣTᵢ = T_Σ            부등식 10개 + 등식 1개
     ∀t:  n·(p(t) − p₀) ≤ 0         부등식 제약 무한개 — 연속체 위에서 성립해야 함
     ∀t:  ‖v(t)‖ ≤ v_max            부등식 제약 무한개

변수 190개에 등식 제약 154개, 그리고 연속 부등식 제약 무한개. 이런 문제를 풀려면 제약을 다루는 기계가 따로 필요합니다.

  • SQP는 매 반복 제약을 선형화한 QP 부분문제를 풉니다 — 내부에 QP 솔버가 또 필요하고 (예: OSQP), 활성집합 추적·라그랑주 승수·메리트 함수가 따라붙습니다.
  • 내부점법은 경계에서 발산하는 장벽항 −μ Σ log(−gᵢ)을 붙이고 μ를 줄여 가며 매번 KKT 시스템을 풉니다. 늘 실현가능 영역 안에 머물러야 합니다.

둘 다 반복 1회 비용이 L-BFGS보다 훨씬 큽니다. L-BFGS 한 반복은 사실상 벡터 내적 몇 번(2중 루프 재귀)이 전부니까요. 50 ms 예산에서는 이 차이가 승부를 가릅니다.

MINCO는 제약을 없애는 서로 다른 수법 세 가지를 겁니다. 셋이 같은 동작이 아니라는 점이 중요합니다 — 앞의 둘은 제약을 정말로 없애고, 마지막 하나는 비용으로 바꿔 놓을 뿐입니다.

직관MINCO에서는
① "그건 네가 정하는 게 아니야"
두 점을 찍으면 그 사이 직선은 하나로 정해집니다. 그런데 직선의 기울기와 절편을 변수로 두고 "두 끝점을 지나야 한다"를 제약으로 거는 건 바보 같은 짓이죠 — 그 둘은 끝점이 정하는 값입니다. 		웨이포인트와 시간을 정하면 최소 저크 궤적은 유일합니다(Theorem 2). 그러니 계수 180개는 변수가 아니라 계산해서 나오는 값입니다. 변수 목록에서 빼면 딸린 제약 153개도 같이 사라집니다.
② "밖으로 나갈 수 없는 좌표계"
0 ≤ p ≤ 1을 지켜야 한다면 보통 솔버에게 제약을 겁니다. 그런데 p = sin²θ로 바꾸면? θ에 무슨 값을 넣든 p는 자동으로 0과 1 사이입니다. 울타리를 치우는 대신 울타리 안쪽만 가리키는 지도를 그린 셈입니다. 		같은 수를 두 번 씁니다 — 시간은 expC2로 (뭘 넣어도 양수, 합이 보존), 웨이포인트는 다면체 꼭짓점의 볼록결합으로 (뭘 넣어도 다면체 안).
③ "벽 대신 벌금"
주차 금지 구역에 차단봉을 세우는 것과 벌금을 매기는 것은 다릅니다. 차단봉은 물리적으로 못 들어가게 하지만, 벌금은 들어갈 수 있습니다 — 비쌀 뿐이죠. 		회랑·속도·가속도의 연속 제약은 없앨 방법이 없어 ρ·max(0, pen)³이라는 비용으로 바꿔 목적함수에 넣었습니다. 궤적은 여전히 회랑을 벗어날 수 있습니다.

①②는 제약이 정말 사라집니다 — 어떤 값을 넣어도 항등적으로 성립하니까요. ③은 남아 있습니다 — 비싸졌을 뿐입니다. 이 차이가 뒤에서 validcheck()가 필요한 이유가 됩니다.

① 최적성 조건계수 c 전부 + 연속성·경계 등식 제약밴디드 시스템의 일부로 흡수예 — 항등적으로
② 매끄러운 사상Tᵢ > 0, ΣTᵢ = T_Σ, 웨이포인트 ∈ 다면체expC2 정규화 · 역 스테레오 사영예 — 항등적으로
③ 시간 적분 항회랑·속도·가속도의 연속 제약K개 샘플에서 ρ·max(0, pen)³아니오 — 비싸게 만들 뿐

①의 실체는 minco.hpp를 열면 바로 보입니다. 경계 조건이 제약이 아니라 밴디드 시스템의 첫 세 행으로 들어가 버립니다. 

// minco.hpp:210-215 — 경계 조건이 연립방정식의 일부가 된다
A(0, 0) = 1.0;  A(1, 1) = 1.0;  A(2, 2) = 2.0;
b.row(0) = headPVA.col(0).transpose();   // p(0) = p₀

흔한 오해 — 변수가 줄어드는 게 아닙니다 "190개에서 몇십 개로 줄었다"고 읽기 쉽지만 사실이 아닙니다. 웨이포인트 하나는 3자유도인데, ②의 역 스테레오 사영은 그것을 다면체 꼭짓점 수 −1 개의 파라미터로 표현합니다 — 과대 파라미터화입니다.

오일러 공식으로 어림하면 면이 F개인 3D 다면체의 꼭짓점은 약 2F−4개입니다. 회랑 5개(N=10, 웨이포인트 9개) 기준으로:

면 8개 → dim_p ≈ 99 → 총 109개  (정직한 버전 190개보다 적음)
면 14개 → dim_p ≈ 207 → 총 217개  (오히려 많음)
면 20개 → dim_p ≈ 315 → 총 325개  (훨씬 많음)

MINCO는 변수를 늘려서 제약을 없앤 거래입니다. L-BFGS는 변수가 늘어도 반복당 비용이 O(mn)으로 선형이지만, 제약이 하나라도 있으면 SQP나 내부점법으로 넘어가야 합니다 — 그쪽이 훨씬 비쌉니다. 그래서 이 거래가 남는 장사입니다.

그리고 그 대가로 얻은 것이 이것입니다 — L-BFGS에게 넘어가는 문제에는 지켜야 할 조건이 하나도 없습니다. 결정변수 벡터에 어떤 실수를 넣어도 유효한 궤적이 나옵니다. 연속성도, 양수 시간도, 총시간도, 웨이포인트의 다면체 소속도 자동으로 성립합니다. 솔버 호출부가 그것을 그대로 보여 줍니다. 

// traj_opt.cc:315 — 제약을 넘기는 자리가 아예 없다
lbfgs_optimize(dim_t_ + dim_p_ + 1,  // 변수 개수
               x_,                     // 시작점
               &minObjective,
               &objectiveFunc,          // 목적함수 + 그래디언트
               nullptr, &earlyExit, this, &lbfgs_params);

인자는 변수 개수 · 시작점 · 목적함수 콜백이 전부입니다. lbfgs_raw.hpp:1103의 시그니처에도 제약을 받는 매개변수가 없습니다. SQP·내부점법이 필요로 하는 것들이 존재하지 않습니다.

중요 — 이 주장은 절반만 참입니다 ③은 소거가 아닙니다. 웨이포인트는 다면체 안에 보장되지만, 웨이포인트 사이의 궤적은 회랑을 벗어날 수 있습니다. ‖v(t)‖ ≤ v_max도 마찬가지입니다. 그 제약들은 제거된 것이 아니라 ρ_P = 10000 같은 큰 가중치로 아주 비싸게 만든 것뿐입니다.

증거가 코드에 있습니다 — planning_nodelet.cpp:731의 validcheck()가 최적화가 끝난 궤적을 0.01초 간격으로 다시 샘플링해 점유 격자와 대조합니다. 제약이 진짜로 보장됐다면 이 검사는 필요 없습니다. 페널티 방식이 모서리를 살짝 깎는 궤적을 내놓을 수 있기 때문에 존재하는 안전망입니다. (setBoundConds가 시작·끝 속도를 vmax로 강제 클램프하는 것도 같은 성격입니다.)

그래서 MINCO 계열은 하드 보장을 포기하고 속도를 산 설계입니다 — 12절에서 볼 MIT의 GCS가 볼록성을 끝까지 유지해 전역 최적에 가까운 해를 얻되 무거운 것과 정확히 반대편입니다.

정리하면 — ①②가 제약을 정말로 없애고 ③이 나머지를 비용으로 바꾼 덕분에 SQP도 내부점법도 필요 없고 L-BFGS 하나로 끝납니다. 다음 05. 솔버 스택이 그 이야기입니다.

이름 정리 MINCO는 궤적 표현(클래스)이고, GCOPTER는 그 표현 위에 회랑·동역학 제약을 얹어 실제로 푸는 프레임워크이자 저장소 이름입니다. 논문에서 "MINCO를 쓴다"는 말은 대개 minco.hpp를 가져다 쓴다는 뜻입니다.

02미분평탄성

MINCO가 왜 위치 다항식만 풀어도 되는가 — 이 계열의 숨은 전제

01절에서 MINCO는 위치 웨이포인트 q와 시간 T를 최적화한다고 했습니다. 그런데 쿼드로터를 실제로 움직이는 것은 모터 4개이고, 자세는 3차원 회전군 SO(3) 위에 있습니다. 위치 다항식 하나를 푸는 것이 어떻게 그 전부를 결정할까요? 미분평탄성이 그 다리입니다.

정의

Fliess, Lévine, Martin, Rouchon이 1995년에 정식화한 개념입니다. 어떤 비선형 시스템에 평탄 출력(flat output) z가 존재해서, 모든 상태와 모든 입력이 z와 그 유한 개 시간 미분의 대수 함수로 쓰이면 그 시스템은 미분평탄합니다.

x(t)= Φ( z,z˙,…, z(q) ) , u(t)= Ψ( z,z˙,…, z(q+1) )

핵심은 적분이 없다는 것입니다. z(t)를 하나 그리면 그 궤적을 따르는 데 필요한 상태와 입력이 미분과 대수 연산만으로 즉시 나옵니다 — 미분방정식을 풀 필요가 없습니다.

계획하는 쪽에서 이게 뜻하는 바는 결정적입니다. 동역학 제약이 사라집니다. z(t)를 충분히 매끄럽게만 그리면 그것은 자동으로 실현 가능한 궤적입니다. 남는 것은 입력 한계뿐이고, 그것도 z의 미분에 대한 조건으로 번역됩니다.

쿼드로터의 평탄 출력

쿼드로터는 입력이 4개(총추력 + 3축 모멘트)이고, 평탄 출력도 4개입니다 — 위치 (x, y, z)와 요각 ψ. Mellinger & Kumar가 2011년에 이것을 쿼드로터에 체계화했고, 그 논문이 곧 minimum snap의 출발점입니다.

사상은 뉴턴 방정식 한 줄에서 시작합니다.

ma+mg e3 = Tb3 ⟹ T=m ‖a+ge3‖ , b3= a+ge3 ‖a+ge3‖ b2= b3×b1d ‖b3×b1d‖ , b1= b2×b3 , R= [b1 b2 b3] (b1d =[cosψ, sinψ,0])

가속도가 자세를 결정합니다. 쿼드로터는 추력을 한 방향(b₃)으로만 낼 수 있으므로, 원하는 가속도를 내려면 기체가 그쪽을 향해야 합니다. 남은 1자유도(b₃ 축 둘레 회전)를 요각 ψ가 채웁니다.

코드에서 그대로 보입니다

Elastic-Tracker의 SO(3) 제어기가 위 식을 거의 글자 그대로 구현하고 있습니다. 피드백 항만 걷어내면 교과서 평탄 사상입니다. 

// so3_controller.hpp — 피드백 항(kx, kv)을 빼면 곧 T·b₃ = m·a + m·g·e₃
force_ = kx∘(p_des − p) + kv∘(v_des − v) + m·a_des + … + m·g·(0,0,1);

b3c = force_.normalized();                       // ← b₃
b1d = (cos(des_yaw), sin(des_yaw), 0);            // ← b₁ᵈ
b2c = b3c.cross(b1d).normalized();                // ← b₂
b1c = b2c.cross(b3c).normalized();                // ← b₁
R << b1c, b2c, b3c;   quat_ = Quaterniond(R);     // ← R
그래서 플래너가 자세를 계산하지 않습니다 Elastic-Tracker의 PolyTraj 메시지에는 위치 계수와 요각 하나뿐입니다. 자세도, 추력도, 바디레이트도 들어 있지 않습니다. traj_server가 p, v, a를 샘플링해 넘기면 so3_controller가 평탄 사상으로 나머지를 복원합니다. 플래너가 SO(3)를 한 번도 건드리지 않는 것이 평탄성 덕분입니다.

이것이 뜻하는 바는 분명합니다. 이 계열은 4차원 평탄 출력 중 3차원만 최적화하고, 나머지 하나는 사후 휴리스틱으로 채웁니다. 추적 임무에서는 "카메라를 목표물 쪽으로"라는 답이 자명하니 잘 통하지만, 요각 자체가 임무에 중요한 경우(가시성이 요각에 민감한 상황, 좁은 틈을 요각으로 통과해야 하는 경우)에는 이 구조가 한계입니다. GCOPTER의 flatness.hpp가 ψ와 dψ를 입력으로 받는 것은 그 확장 여지를 열어 둔 것입니다.

위 식은 가속도까지만 씁니다. 그런데 왜 저크(3계)와 스냅(4계)을 최소화할까요? 미분을 한 단계 더 내려가면 무엇이 나오는지를 보면 답이 나옵니다.

UZH 그룹이 "선형 로터 항력이 걸린 쿼드로터 동역학이 위치와 헤딩에 대해 미분평탄함을 증명"했습니다. 항력을 미지의 외란으로 두고 피드백으로 때우는 대신 모델 안에 넣어도 평탄성이 유지된다는 뜻이고, 고속 궤적 추종 오차를 크게 줄입니다.

GCOPTER의 flatness.hpp가 이것을 구현합니다. FlatnessMap::forward()는 속도·가속도·저크·요각·요각속도를 받아 추력·쿼터니언·바디레이트를 내놓고, backward()는 그 출력에 대한 그래디언트를 다시 위치 미분 쪽으로 되돌립니다.

이것이 GCOPTER만의 자산입니다 backward()가 있다는 것은 "추력이 최대치를 넘지 마라", "바디레이트가 한계를 넘지 마라"를 궤적 최적화의 비용 항으로 직접 걸 수 있다는 뜻입니다 — 01절에서 말한 "flatness map의 역방향 미분"이 이것입니다.

나머지 넷은 이걸 갖고 있지 않습니다. Elastic-Tracker와 EGO-Planner-v2는 ‖v‖ ≤ v_max, ‖a‖ ≤ a_max라는 대리 제약만 겁니다. 가속도 한계는 추력 한계의 근사일 뿐이고, 자세가 기울수록 그 근사가 나빠집니다.

지상 로봇의 평탄성 — DDR-opt의 진짜 기여

유니사이클(차동구동) 모델도 미분평탄합니다. 평탄 출력은 위치 (x, y)뿐이고, 나머지가 전부 거기서 나옵니다.

x˙=vcosθ , y˙=vsinθ , θ˙=ω θ= atan2(y˙,x˙) , v=± x˙2+y˙2 , ω= x˙y¨−y˙x¨ x˙2+y˙2

분모가 ẋ² + ẏ² = v²입니다 — v = 0에서 전부 무너집니다. θ는 atan2(0, 0)으로 미정이고, ω는 0/0입니다.

쿼드로터의 자유낙하 특이점은 실제 비행에서 거의 만나지 않습니다. 그런데 지상 로봇의 v = 0은 상시적입니다 — 출발할 때, 멈출 때, 제자리에서 회전할 때, 전진에서 후진으로 바꿀 때마다 지나갑니다. 비행체용 평탄성 기법을 그대로 가져오면 정확히 그 지점에서 깨집니다.

DDR-opt의 답이 여기 있습니다. 논문은 궤적 표현을 "운동 상태 또는 그 적분값 — 이를테면 각속도와 선속도 — 의 다항식 파라미터화"라고 설명하며, 그것이 "로봇의 운동을 제어 원리에 본질적으로 맞춘다"고 씁니다.

읽어 보면 (x, y)를 다항식으로 두면 v와 ω가 나눗셈으로 유도되어 v = 0이 특이점이 됩니다. 반대로 (v, ω)를 다항식으로 두면 v = 0은 그냥 다항식이 지나가는 한 값일 뿐이고, (x, y)는 적분으로 나옵니다 — 나눗셈이 사라집니다.

DDR-opt가 왜 "universal"을 표방하며 이륜·스키드스티어·무한궤도를 한 틀로 덮는지도 여기서 설명됩니다. 구동 방식이 달라도 결국 (v, ω)로 제어하기 때문입니다.
— 이 문단은 논문 초록의 서술을 근거로 한 해석이며, DDR-opt 최적화기 소스를 직접 읽고 확인한 것은 아닙니다.

04두 축으로 보는 지형도

이 다섯을 가르는 결정적 차이는 두 가지뿐입니다

축 1 — 궤적을 무엇으로 표현하는가. B-스플라인은 제어점의 볼록포 성질로 안전성을 얻지만 시간 배분이 균일 노트에 묶여 뻣뻣합니다. MINCO는 웨이포인트 P와 구간 시간 T만으로 다항식이 결정되므로 시간이 최적화 변수가 됩니다. 결정변수를 나란히 쓰면 차이가 한눈에 보입니다.

B-스플라인 — ego-planner
p(t)= ∑i=0n Qi Bi,k (t) , Δt=const
결정변수 Q ∈ ℝ3×(n+1) — 제어점만.
노트 간격이 균일하게 고정되어 시간은 변수가 아닙니다. 동역학이 안 맞으면 사후에 전체를 늘립니다.
MINCO — GCOPTER 계열
p(t)= M (P,T) , T∈ R>0N
결정변수 P ∈ ℝ3×(N−1) 그리고 T ∈ ℝN.
계수는 대역폭 6 밴디드 시스템을 O(N)에 풀어 얻습니다. 시간이 최적화 안에 있습니다.

같은 최소 제어 노력 문제를 풀지만, 오른쪽만 시간 배분이 결정변수입니다. Elastic-Tracker의 "탄성"은 여기에 총 시간 TΣ = Ts + δ²를 하나 더 얹은 것입니다.

뉴턴법은 헤시안 n×n을 만들고 뒤집어야 합니다. 이 계열의 결정변수는 수백~수천 개라 그건 불가능합니다. L-BFGS는 헤시안을 아예 만들지 않고, 최근 m번의 (스텝 s, 그래디언트 변화 y) 쌍만 들고 2중 루프 재귀로 −H·g 방향을 바로 계산합니다. 메모리가 O(mn)으로 끝납니다.

채택 사례는 사실상 표준입니다 — SciPy minimize(method='L-BFGS-B'), PyTorch torch.optim.LBFGS, R optim, 그리고 대부분의 로보틱스 궤적 최적화기.

GCOPTER 헤더가 그 이유를 직접 밝힙니다 — Lewis–Overton은 "backtracking만큼 견고하면서, strong Wolfe 조건이 대개 성립하지 않는 연속·조각별 매끄러운 함수에까지 적용된다."

왜 중요한가 이 계열의 비용 함수는 조각별로만 매끄럽습니다. Elastic-Tracker의 penF는 x = 2ε에서 값과 1계 도함수만 이어지고 2계 도함수는 점프합니다 (4차 → 선형). 그런 지점에서 strong Wolfe 조건은 보장되지 않습니다. 즉 Elastic-Tracker는 자기 비용 함수보다 한 세대 오래된 라인서치를 쓰고 있습니다. 실패 시 backtracking 폴백이 있어 실용상 돌아가지만, 최신 GCOPTER를 가져오면 이론적 정합성이 맞습니다.

다면체를 표현하는 방법은 두 가지입니다 — H-표현(반공간 부등식의 교집합)과 V-표현(꼭짓점의 볼록포). DecompROS와 FIRI가 만들어 주는 건 H-표현인데, MINCO의 웨이포인트 파라미터화는 꼭짓점이 있어야 볼록 결합을 만들 수 있습니다.

그 변환이 geoutils::enumerateVs이고, 내부에서 QuickHull을 씁니다. 먼저 SDLP로 내부점을 찾아 원점을 옮긴 뒤 극쌍대(polar dual)를 취하면 H-표현의 꼭짓점 열거가 볼록껍질 문제로 바뀝니다. 그래서 두 솔버가 항상 붙어 다닙니다.

실패 지점 extractVs가 실패하면 generate_traj가 즉시 false를 반환합니다. 회랑이 퇴화해(거의 납작해져) 꼭짓점 열거가 불가능할 때입니다 — Elastic-Tracker 실행 중 보게 되는 ROS_ERROR("extractVs fail!")가 이 경로입니다.

궤적 한 조각의 최대 속력을 알아야 한다고 합시다. 흔한 방법은 조각을 잘게 샘플링해 최댓값을 취하는 것인데, 샘플 사이의 첨두를 놓칩니다.

MINCO는 궤적이 다항식이라는 사실을 그대로 이용합니다. ‖v(t)‖²도 다항식이므로, 그 도함수의 근을 전부 찾아 후보에 넣고 양 끝점과 함께 비교하면 최댓값이 정확히 나옵니다. 

coeff = polySqr(vx) + polySqr(vy) + polySqr(vz)   // ‖v(t)‖²
coeff *= d/dt                                     // 도함수
candidates = solvePolynomial(coeff, l, r, tol)     // 모든 실근
candidates ∪ {0, 1}                               // 끝점 포함
maxVelRate = max over candidates                  // 정확한 최댓값

다섯 저장소 중 DDR-opt만 별도의 QP 솔버를 씁니다. 궤적 최적화가 아니라 그 궤적을 따라가는 mpc_controller / nmpc_controller 때문입니다. MPC는 매 주기 같은 구조에 데이터만 바뀐 QP를 푸는데, OSQP가 정확히 그 형태를 겨냥합니다.

푸는 문제는 min ½xᵀPx + qᵀx s.t. l ≤ Ax ≤ u이고, 특징이 넷입니다.

  • 인수분해 1회 재사용 — 준정부호 KKT 행렬을 한 번만 분해하고 모든 반복에서 재사용
  • 나눗셈 없음 — 초기 분해 이후 나눗셈이 사라져 임베디드 하드웨어에 적합
  • 웜스타트 — 이전 주기 해에서 출발. MPC에서 결정적입니다
  • 실현불가능 증명서 — 원문제/쌍대문제 실현불가를 반복열에서 검출하는 최초의 연산자 분할법

채택: CVXPY의 기본 QP 백엔드이고, 임베디드 MPC에서 널리 씁니다. 저자들은 같은 조건에서 내부점법 대비 통상 10배, 인수분해 캐싱·웜스타트를 쓰면 그보다 더 빠르다고 보고합니다.

요구 조건이 느슨한 것도 실전에서 큰 값입니다 — P가 양정부호일 필요도, 제약이 선형독립일 필요도 없습니다. 지상 로봇처럼 모델이 지저분한 경우에 맞는 선택입니다.

GCOPTER는 예제에서 전역 경로를 OMPL로 뽑고, 그 경로에 FIRI로 회랑을 씌운 뒤 MINCO로 최적화합니다. 다른 네 저장소는 OMPL을 쓰지 않고 자체 A*를 씁니다 — Elastic-Tracker의 env.hpp에 A*가 세 벌 들어 있는 게 그 이유입니다.

OMPL은 의도적으로 충돌 검사와 시각화를 포함하지 않습니다. 상태 공간과 샘플러 추상화만 제공하고 충돌 판정은 사용자가 꽂습니다. 덕분에 특정 충돌 검사기에 묶이지 않지만, 반대로 바로 쓸 수 있는 물건이 아닙니다 — 로컬 격자에 A*를 직접 짜는 편이 가볍다는 판단이 나머지 저장소의 선택입니다.

결론은 이 한 줄입니다 — 솔버에게 넘길 때 제약이 남아 있지 않으면 제약을 다루는 솔버가 필요 없습니다. 01절의 세 수법이 끝나면 L-BFGS가 받는 것은 지켜야 할 조건이 하나도 없는 문제이고, 거기에는 L-BFGS가 가장 싼 도구입니다.

단, 공짜는 아닙니다 세 번째 수법(①②③ 중 ③)은 제약을 없앤 것이 아니라 목적함수의 페널티로 옮긴 것입니다. 회랑과 동역학 제약은 보장되지 않습니다 — ρ_P = 10000으로 비싸게 만들었을 뿐입니다. 그래서 최적화가 끝난 뒤에도 validcheck()가 궤적을 다시 샘플링해 점유 격자와 대조해야 합니다. SQP·내부점법을 안 쓰는 대가로 하드 보장을 내준 것입니다.
뒤집어 보면 이 설계는 제약을 소거하거나 페널티로 바꿀 수 있는 문제에만 적용됩니다. 볼록 다면체 안쪽처럼 매끄러운 사상이 존재하는 제약이라야 하고, 비볼록 제약이나 정수 결정(어느 회랑을 지날지 고르기)은 이 틀 밖에 있습니다. 회랑을 미리 정해 두는 프런트엔드(A*/OMPL + 회랑 생성)가 반드시 앞에 붙는 이유입니다.

읽어 낸 것 넷

① 시간 배분만으로 저크가 3~4배 A와 B는 경로가 완전히 같고 총 시간도 같습니다. 웨이포인트도 같습니다. 다른 것은 그 시간을 조각들에 어떻게 나누는가 하나뿐입니다. 그런데 ∫jerk²가 3.8배 · 4.3배 · 3.2배로 벌어지고, B는 속도 한계를 넘습니다 (3.41 · 3.24 · 3.23 m/s, 한계 3.0).

속도 프로파일이 그 이유를 보여 줍니다 — A는 한계에서 평탄한 구간을 만들지만 B는 계속 요동칩니다. 같은 길을 같은 시간에 가는데 한쪽만 매끄럽습니다. 01절의 "시간이 최적화 변수"라는 말의 실측값이 이것입니다.
② 웨이포인트를 풀어 주면 시간이 30~40% 준다 C는 A* 경로점을 그대로 통과해야 합니다. 그 결과 같은 동역학 한계에서 T가 1.39~1.42배 걸리고 ∫jerk²는 6~7배입니다. 회랑을 주고 그 안에서 웨이포인트를 자유롭게 두는 것이 길이(+3~5%)보다 시간과 부드러움에서 훨씬 크게 돌아옵니다.
③ B-스플라인은 여유를 크게 벌지만 스냅을 잃는다 D의 최소 여유는 A의 3.2~4.5배입니다 — 앵커가 궤적을 장애물에서 힘껏 밀어냅니다. 대신 경로가 7~10% 길고, ∫snap²가 64~172배입니다.

스냅 차이는 튜닝이 아니라 구조적입니다. 3차 B-스플라인은 노트에서 저크가 불연속이라 스냅이 임펄스로 튑니다. MINCO(s=3, 5차)는 Theorem 2에 따라 접합부에서 스냅까지 연속입니다. 표현을 고른 순간 정해지는 성질입니다.
④ 매끄러운 페널티는 끝내 제약을 정확히 만족시키지 못한다 01절 ③과 KKT 논의에서, 매끄러운 3차 페널티는 제약을 정확히 만족시킬 수 없고 항상 조금 벗어난 곳에 앉는다고 했습니다. 실제로 측정됩니다 — 페널티가 보는 경계(회랑을 clearance_d만큼 안으로 민 면) 기준 14.9 · 12.2 · 17.1 cm의 잔여 위배가 남습니다.

11계획과 제어의 경계

MPCC와 CMPCC — 시간표를 언제 정할 것인가

이 문서가 지금까지 다룬 것은 전부 궤적 생성입니다. 생성된 궤적은 "시각 t에 위치 p"라는 시간표를 주고, 별도의 추종 제어기가 그걸 따라갑니다. 그런데 그 분리에는 대가가 있습니다 — 궤적은 계획 시점의 세계만 압니다. 바람이 불거나 모델이 틀리거나 기체가 밀리면, 제어기는 이미 뒤처진 채로 원래 시간표를 쫓아가려 합니다.

윤곽 제어 — 시간표를 버리기

Contouring control은 참조를 시간의 함수가 아니라 경로의 함수로 봅니다. 진행도(progress) θ를 상태에 추가하고 두 가지를 동시에 최적화합니다.

  • 윤곽 오차(contouring error) — 경로에서 벗어난 거리. 최소화
  • 진행도(progress) — 경로를 따라 나아간 정도. 최대화

"정해진 시각에 정해진 위치"가 아니라 "경로에 붙어 있으면서 가능한 한 빨리"입니다. 시간표 자체가 사라집니다. 뒤처져도 쫓아갈 시간표가 없으니 뒤처졌다는 개념이 없습니다 — 그냥 현재 위치에서 다시 최대한 나아갈 뿐입니다.

남은 공백

정밀화한 공백 협조적 가림체는 Swarm-Tracker가 MINCO 안에서 이미 풀었고, 동적 장애물을 시야에 두는 것은 PANTHER가 풀었습니다. 비어 있는 것은 셋이 한꺼번에 걸리는 경우입니다 — ① 궤적을 모르는 비협조 가림체를 예측 불확실성과 함께, ② 기체 자세가 정하는 3D 시야 안에서, ③ Elastic-Tracker식 탄성 시간으로 추적하는 문제.

가장 짧은 경로는 Swarm-Tracker의 방송 궤적 pj(t)를 예측 궤적 + 도달 영역 팽창(DYNUS · SANDO)으로 바꾸는 것입니다.

동적 가림 — 정식화

공백을 비용 한 줄로 옮겨 봅니다. 표적 샘플 i, 가림체 j에 대해 시선 선분 [p(ti), gi]와 가림체 중심 oj(ti) 사이의 거리를 쓰면 됩니다.

u=gi−p , λ=clamp ( (oj−p)·u‖u‖2 ,0,1 ) , q=p+λu c=w [ (rj+m)2 − ‖oj−q‖2 ]+3 , ∂c∂p =6w pen2 (1−λ) (oj−q)

q는 선분 위의 최근접점이므로 λ에 대한 미분이 0입니다(포락선 정리). 그래서 λ가 0이나 1에서 잘릴 때도 (1 − λ) 한 인자로 연속입니다. 이 인자에 뜻이 있습니다 — 가림체가 표적에 붙어 있으면(λ → 1) 드론을 움직여도 소용이 없고, 그래디언트도 저절로 0이 됩니다.

경쟁자가 다른 곳산업 지상 로봇 — 상대는 학습이 아니라 샘플링 MPC입니다. 비미분 코스트맵과 학습 비용을 그대로 쓸 수 있기 때문입니다 [N1][N12]
맞지 않는 곳불연속 접촉 · 이산 발디딤 · 전신 토크 제약 — 한국 최신 연구도 여기서 RL이나 contact-implicit MPC를 택했습니다 [K3][K4]

이 자리에 들어가려면 MINCO 쪽에 네 가지가 더 필요합니다.

  • 입력 인터페이스 — 외부 경유점·통로, 제약 가중치, 객체 재분류 같은 의미 라벨을 받는 경로. 원격·파운데이션 모델 힌트는 150 ms에서 수 초 늦게 비동기로 도착합니다 [P7][P10].
  • 보증의 빈칸 메우기 — GCOPTER는 통로 제약을 사상으로 정확히 없애지만 연속시간 동역학 제약은 샘플 지점의 페널티입니다(01절의 ③). 사후 검증기와 최소위험기동 fallback이 붙어야 "배치할 수 있는 층"이 됩니다 — ENav의 보수적 충돌 검사가 그 예입니다 [P13].
  • 비미분 비용과 국소해 — GPU 병렬 다중 초기화, 학습 prior, 샘플링 롤아웃과 경사 정제의 결합 [C10].
  • 비홀로노믹 · 접촉 시스템 — Frenet·yaw-호길이 매개화와 하위 추종기(MPC·RL)를 함께 설계해야 합니다.
14절과의 연결 14절의 로드맵은 ③ 3층 구조의 가운데 층을 드론 추적에서 키우는 작업으로 읽을 수 있습니다 — 비협조 가림체의 예측을 학습 모듈이 준다면 그대로 3층 구조가 됩니다. 표적 추적 드론에서 학습 방식이 MINCO를 대체했다는 직접 증거는 2026-09 기준으로 찾지 못했습니다. 이 연결은 해석입니다.
읽을 때 주의 "대세"는 공개된 사례에 한정한 판단입니다. PoliMOVE · Cavalier, Tesla Optimus · 1X, 광산 OEM, 중국 사족 OEM, 국내 배송 로봇 기업은 계획·제어 알고리즘을 공개하지 않았습니다.
