01핵심 아이디어

무엇이 새로운가 — 세 가지 보장

일반적인 궤적 플래너는 구간 시간 T = (T₁ … T_N)을 미리 고정하고 형상만 최적화합니다. 목표물이 갑자기 가속하거나 멈추면 그 고정된 시간 배분이 곧바로 부적합해집니다.

Elastic Tracker는 전체 소요 시간을 결정변수 자체로 둡니다. 목적함수 안에서 총 시간이 이렇게 만들어집니다. 

// traj_opt.cc:177-180 — 마지막 결정변수 하나가 시간 여유분
double deltaT = x[obj.dim_t_ + obj.dim_p_];
double sumT   = obj.sum_T_ + deltaT * deltaT;   // sum_T_ = tracking_dur = 3.0 s
forwardT(t, sumT, T);                          // sumT를 N개 구간으로 분배
TΣ= Ts+ δ2 ⟹ TΣ≥ Ts (∀ δ ∈ ℝ)

Ts = tracking_dur = 3.0 s (하한) · δ = deltaT, 무제약 실수 · 비용에 ρTδ²가 더해져 시간 연장에 값을 매깁니다

deltaT를 제곱해서 더하므로 총 시간은 3초 아래로 절대 내려가지 않으면서 위로는 자유롭게 늘어납니다. 목표물이 빨라지면 궤적이 늘어나고, 느려지면 줄어듭니다 — 이것이 "탄성(elastic)"이라는 이름의 근거이고, 아래 세 가지 보장 중 하나입니다.

그런데 forwardT는 이 TΣ를 N개 구간에 나눠야 하고, 각 구간은 양수여야 하며, 합은 정확히 TΣ여야 합니다. 제약 세 개를 무제약 변수 M = N−1개로 푸는 사상이 이것입니다.

Ti= TΣ ei 1+∑j=1Mej (i≤M) , TN= TΣ 1+∑j=1Mej ei= expC2(ti) = { 12ti2+ti+1 ti>0 (12ti2−ti+1)−1 ti≤0

expC2는 항상 양수이고 C² 연속입니다 — exp보다 싸고 오버플로가 없습니다. 분모의 1 + 덕분에 Σ Ti = TΣ가 항등적으로 성립합니다.

왜 무제약으로 풀 수 있는가

MINCO 표현을 쓰면 5차 다항식 N조각 궤적이 중간 웨이포인트 P와 구간 시간 T만으로 유일하게 결정됩니다. 다항식 계수는 대역폭 6의 밴디드 선형 시스템을 O(N)에 풀어 얻습니다. 여기에 두 개의 변수 변환을 얹으면 부등식 제약이 전부 사라집니다.

결정변수차원변환보장되는 것
tN − 1expC2 + 합 정규화모든 T_i > 0, 그리고 ΣT_i = sumT
pΣ(Vi − 1)역 스테레오 사영웨이포인트가 항상 해당 다면체 안쪽
deltaT1제곱총 시간이 tracking_dur 이상

제약 처리 루틴이 필요 없으니 L-BFGS 하나로 끝납니다. 이것이 전 파이프라인을 20 Hz로 다시 도는 것을 가능하게 하는 실질적 이유입니다.

04목표물 예측

prediction.hpp:56 · 등가속도 격자 탐색

EKF가 주는 것은 현재 위치와 속도뿐입니다. 3초 뒤까지의 궤적을 얻기 위해 "장애물에 부딪히지 않으면서 가속을 가장 적게 쓰는" 경로를 탐색합니다. 단순 등속 외삽이 아닙니다. 

// prediction.hpp:81-90 — 수평 가속 9가지 분기
for (input.x() = -3; input.x() <= 3; input.x() += 3)      // {-3, 0, 3} m/s²
  for (input.y() = -3; input.y() <= 3; input.y() += 3) {
    p = curPtr->p + curPtr->v * dt + input * dt²/2;
    v = curPtr->v + input * dt;
    if (!isValid(p, v)) continue;    // |v| < vmax && !isOccupied(p)

z축 가속은 항상 0이므로 예측은 수평면 운동만 모델링합니다. 차량 추적에는 적절한 가정이고, 공중 목표물을 3D로 추적하려면 여기부터 손대야 합니다.

비용

g(n) = Σ ρ_a·|a_i| (누적 가속), h(n) = 0.001·|p_n − p_end|. 휴리스틱 가중치가 0.001로 극단적으로 작아 사실상 다익스트라에 가까운 최소 가속 탐색입니다 — 정책으로 읽으면 "가능하면 등속으로, 벽을 만나면 최소한만 꺾는다"가 됩니다.

종료

while (curPtr->t < pre_dur) — 목표 지점 도달이 아니라 시간 지평 도달이 종료 조건입니다. 즉 항상 3초짜리 예측이 나오고, 점 개수는 3.0 / 0.2 + 1 = 16개로 고정입니다. 예산은 노드 2²² = 4,194,304개와 벽시계 100 ms이며, 둘 중 하나를 넘기면 실패를 반환하고 플래너는 그 사이클을 포기합니다.

메모리 주의 Predict 생성자가 MAX_MEMORY = 1 << 22개의 Node를 개별 new로 할당합니다 — 약 400 MB, 419만 번의 할당입니다. 노드렛 초기화가 눈에 띄게 느린 주 원인이고, 소멸자가 없어 프로세스 종료까지 해제되지 않습니다. 실제로는 100 ms 제한이 먼저 걸리므로 1 << 20 정도로 줄여도 충분해 보입니다.

05가시 경로 탐색

env.hpp:410 · 링 휴리스틱 A*

일반 A*는 목표 지점으로 수렴합니다. 여기서는 목표물 주위의 원(반지름 tracking_dist)으로 수렴해야 합니다. 휴리스틱 한 줄이 그 차이를 만듭니다. 

// env.hpp:417-427
double stop_dist = desired_dist_ / resolution;      // 링 반지름 (셀)
Eigen::Vector3i dp = end_idx - ptr->idx;
double dr     = dp.head(2).norm();
double lambda = 1 - stop_dist / dr;                  // ← 링까지 남은 비율
double dx = lambda*dp.x(), dy = lambda*dp.y(), dz = dp.z();
ptr->h  = fabs(dx) + fabs(dy) + abs(dz);
ptr->h += 0.001 * (fabs(dx*dy0 - dy*dx0) + abs(dz));  // 외적 타이브레이커

lambda가 목표물까지의 벡터를 링 위 지점까지의 벡터로 축소합니다. 외적 항은 동일 비용 경로 중 직선에 가까운 쪽을 골라 6-연결 격자 특유의 계단 경로를 억제합니다.

λ= 1− rring‖dp‖ ⟹ ‖λdp−dp‖ =rring

λ의 부호와 무관하게 성립합니다 — 노드에서 λ·dp만큼 간 지점은 항상 링 위입니다. 이것이 이 휴리스틱의 전부입니다.

종료 조건은 두 개

// env.hpp:414-416
return ptr->h < tolerance_d_ / resolution   // 링 위에 도달했고
       && rayValid(ptr->idx, end_idx);      // 목표물까지 시선이 뚫려 있다

거리만이 아니라 가시성까지 종료 조건에 들어간다는 점이 이 A*를 특별하게 만듭니다. 예측된 목표물 위치 16개에 대해 이 A*가 체인으로 실행되고, 각 도착점이 way_pts에 쌓입니다.

드론을 끌거나 슬라이더를 쓰세요. θ_clearance를 1.05 이상으로 올리면 θ_less가 0이 되어 허용 영역이 중심선 하나로 붕괴합니다 — 시야가 좁을수록 제약이 강해진다는 뜻입니다. 거리를 2.2 밖으로 밀면 추적 비용이 따로 살아납니다.

부채꼴은 t_l에서 t_r까지, 중심선은 θ_v = (t_l + t_r)/2, 반각은 θ = (t_r − t_l)/2. 위 그림의 θ는 60°로 고정해 두었습니다.

a=p−c , b=pvis−c , θless= max(θ−θc,0) pen= cosθless − a·b ‖a‖‖b‖ , Jvis= ρvis [pen]3 (pen > 0 일 때만)

코사인끼리 비교하므로 역삼각함수가 필요 없습니다 — acos 한 번 없이 각도 제약이 걸립니다. pen > 0은 드론이 허용 원뿔 밖이라는 뜻입니다.

시드를 안쪽으로 미는 부분

visible_pair()는 부채꼴만 계산하고 끝나지 않습니다. 시드가 가장자리에 너무 붙어 있으면 직접 안쪽으로 밀어 넣습니다.

시간 변수 변환

T_i > 0과 ΣT_i = sumT를 동시에 만족시켜야 합니다. M = N−1개의 자유 변수로 N개의 시간을 만들되 합이 정확히 보존되는 사상을 씁니다. 

// traj_opt.cc:12-30
static double expC2(double t) {          // 항상 양수, C² 연속, exp보다 싸고 오버플로 없음
  return t > 0 ? ((0.5*t + 1.0)*t + 1.0)
               : 1.0 / ((0.5*t - 1.0)*t + 1.0);
}
static void forwardT(t, sT, vecT) {
  for (i < M) vecT(i) = expC2(t(i));
  vecT(M) = 0.0;
  vecT /= 1.0 + vecT.sum();               // 정규화
  vecT(M) = 1.0 - vecT.sum();             // 마지막 조각은 나머지
  vecT *= sT;
}

웨이포인트 변수 변환

각 웨이포인트를 다면체 꼭짓점들의 볼록 결합으로 표현하되, 가중치를 무제약 파라미터로 만듭니다. 

// traj_opt.cc:73-76 — 역 스테레오 사영
q = 2.0 / (1.0 + |p|²) * p;                      // |q|² ≤ 1 이 항상 성립
inP.col(i) = cfgPolyVs[i].rightCols(k) * q.cwiseProduct(q)
           + cfgPolyVs[i].col(0);                // → 언제나 다면체 안쪽
q= 2p1+‖p‖2 , w=q∘q , x=Vw+v0 1−‖q‖2 = 1− 4s(1+s)2 = (1−s)2(1+s)2 ≥0 (s=‖p‖2)

한 줄짜리 항등식이 전부입니다. ‖q‖² ≤ 1이 모든 p에 대해 성립하므로 w는 항상 유효한 볼록 결합 가중치(wk ≥ 0, Σwk ≤ 1)가 되고, V의 열이 다면체 꼭짓점이므로 x는 언제나 그 안쪽입니다.

q∘q(성분별 제곱)의 합이 1 이하이므로 볼록 결합의 가중치로 유효합니다. 어떤 p 값에 대해서도 결과가 다면체를 벗어나지 않습니다. 꼭짓점 열거는 quickhull.hpp, 초기값은 backwardP가 128회 L-BFGS 최소제곱으로 구합니다.

변수 배치 extractVs는 다면체 M+1개에 대해 i번째 다면체 자체와 i와 i+1의 교집합을 번갈아 넣어 2M+1개의 볼록 영역을 만듭니다. N = 2(M+1)이므로 중간 웨이포인트 수 N−1 = 2M+1과 정확히 일치합니다 — 웨이포인트 하나당 담길 영역이 정확히 하나씩 배정되는 구조입니다.

경계 초과

노드 풀 경계 검사 없음

env.hpp:66

visit()가 data_[visited_nodes_.size()]를 경계 검사 없이 인덱싱합니다. 루프 가드는 size < MAX_MEMORY지만, 본문 안에서 이웃 6개에 대해 visit()가 최대 6번 호출되므로 크기가 가드를 넘어설 수 있습니다. 

size == MAX_MEMORY - 1 에서 루프 진입 (가드 통과)
  1번째 이웃 → data_[MAX_MEMORY - 1]   ✔ size = MAX_MEMORY
  2번째 이웃 → data_[MAX_MEMORY]       ✘ 배열 밖
  ⋮
  6번째 이웃 → data_[MAX_MEMORY + 4]   ✘

최대 5개까지 범위 밖을 읽고 그 쓰레기 포인터에 ptr->idx = idx를 씁니다. 루프 하단의 if (size == MAX_MEMORY) cout << "out of memory"는 출력만 하고 break하지 않습니다 — 다음 반복의 가드가 잡지만 초과 접근은 이미 끝난 뒤입니다. 세 A* 함수가 모두 같은 visit()를 공유합니다.

추적 모드 EMERGENCY STOP 조건 반전

planning_nodelet.cpp:415

실시간성

A* 시간 예산이 실제로는 발동하지 않음

env.hpp:454–458 
double t_cost = (ros::Time::now() - t_start_).toSec();   // 루프 진입 전 1회만
while (visited_nodes_.size() < MAX_MEMORY && t_cost <= MAX_DURATION) {
  ...                                    // 본문 어디에서도 t_cost 갱신 없음
}

t_cost가 루프 조건에 있지만 본문에서 갱신되지 않습니다. 한 번의 A*는 일단 시작하면 0.2초와 무관하게 메모리를 다 쓰거나 open_set이 빌 때까지 돕니다.

완전히 무의미하지는 않습니다. t_start_는 바깥 findVisiblePath에서 한 번만 찍히고 체인의 각 A*가 진입 시 t_cost를 새로 계산하므로 16회 호출 사이사이에는 검사가 걸립니다. 최악의 경우는 "16 × 0.2초"가 아니라 "0.2초 + 단일 A*의 최대 소요 시간"입니다. 50 ms 예산을 지키려면 루프 안에서 주기적으로 다시 재야 합니다.

축 혼동

링버퍼 이동 시 z축 크기 오류

mapping.cc:26 
from[i]       = move[i] + size_xyz[i];              // ✔ 축별 크기
from_small[i] = move[i] + size_x - inflate_size;    // ✘ 항상 x축 크기

같은 블록의 나머지 세 줄은 모두 size_xyz[i]를 쓰므로 오타로 보입니다. 기본 격자가 128 × 128 × 32이라 x·y축은 우연히 맞고 z축만 틀립니다 — 96만큼 과대.

영향받는 것은 로그오드 확률 버퍼 pro를 p_def로 초기화하는 루프입니다. 드론이 아래로 이동할 때 from_small.z() > to_small.z()가 되어 루프가 아예 돌지 않고, 새로 들어온 z 슬래브에 이전 위치의 확률값이 남습니다. infocc를 지우는 루프는 from/to를 쓰므로 정상 — 즉 표시되는 격자는 맞지만 그 아래 확률 상태에 유령 값이 남습니다. 수정은 한 단어입니다.

논리 오류

generateSFC의 current_poly 오참조

env.hpp:336–343

수축 여부 판정이 루프 변수 hPolys[i]가 아니라 직전 루프에서 남은 current_poly(마지막 다면체)를 검사합니다. 게다가 그 사이에 filterCorridor(hPolys)가 실행되어 hPolys의 내용이 바뀌었으므로, current_poly는 어떤 원소와도 대응이 보장되지 않습니다.

결과적으로 조건이 모든 i에 대해 동일하게 평가됩니다 — 전부 수축하거나, 전부 수축하지 않거나. 다행히 바로 아래 연결성 보정 루프가 교집합 소멸이라는 최악의 경우는 막아 줍니다.

미정의 동작

초기화되지 않은 반환 플래그

traj_opt.cc:634, :675

grad_cost_p_tracking과 grad_cost_p_landing이 bool ret;을 초기화 없이 선언합니다. 세 위배 조건이 모두 거짓이면 — 추적 거리와 고도가 모두 정상 범위일 때 — 초기화되지 않은 값을 반환합니다.

실제 영향은 제한적입니다. costp와 gradp는 0으로 초기화되어 있어 ret이 우연히 참이 되어도 addTimeCost가 0을 더할 뿐입니다. 다만 같은 파일의 grad_cost_v, grad_cost_a, grad_cost_visibility는 모두 명시적으로 return false합니다 — 이 두 함수만 패턴이 다릅니다.
